## Changes

- Reuse an existing native Codex login when Claudodex has no direct login. Codex keeps ownership of credential refresh; Claudodex does not copy its refresh token. Explicit logout disables automatic reuse until it is enabled again.
- Discover model routes on every launch: Haiku uses Luna, Sonnet uses Terra, Opus uses Sol, and Fable uses Astra. Choose the newest available generation in each family while preserving explicit model IDs.
- Use the selected models' metadata for context limits, reasoning efforts, defaults, and fast-mode support across routing, settings, the model picker, and the statusline.
- Continue startup during temporary catalog failures using a private cache valid for up to 24 hours. Cache entries are isolated by account, backend, region, and client protocol; authentication and permanent catalog failures do not use stale metadata.
- Retain verified Claude Code 2.1.316 compatibility and the signed, consent-based Homebrew update flow.

## Verification

- Full Go tests, affected-package race tests, formatting, vet, and build passed.
- Installed Claude Code 2.1.316 startup, model, effort, tool, UI, and fallback checks passed with controlled upstream responses.
- Native Codex login reuse and live model metadata were verified without model generation or copying refresh tokens.

## Compatibility notes

- Native Codex login reuse requires the native CLI and an identifiable local login. A direct Claudodex login takes priority.
- Explicit model pins remain exact. An unavailable family or pin produces an actionable error rather than selecting another family.
- Thinking traces and transcript signatures are unchanged in this release.
